<KeyTakeaways>

- Map and measure the workflow before you automate it.
- Automate frequent, rule-based tasks first; keep judgement human.
- Decide build versus buy with a simple table, not enthusiasm.
- Prove value on one workflow, then expand.

</KeyTakeaways>

Automation fails when it starts with a tool. It works when it starts with a workflow you understand. This guide gives you a method for finding what to automate, deciding how, and checking that it paid off. For help, see [LLM reporting automation](/services/llm-reporting-automation/).

## 1. Run a workflow audit

List the recurring tasks in a team over a typical month. For each one record:

| Field | Example question |
|---|---|
| Task | What exactly is done? |
| Frequency | How often? |
| Time per run | How long does one run take? |
| People involved | Who touches it? |
| Inputs and outputs | What goes in, what comes out? |
| Error cost | What happens if it is wrong? |

Ask the people doing the work, not only their managers. They know where the time really goes.

## 2. Prioritise

Score each task on frequency, how rule-based it is, how cheap a mistake is and whether the data is available. High scorers are first candidates. The [AI marketing automation guide](/guides/ai-marketing-automation/) has a full scorecard.

## 3. Map the process

Draw the current steps, including the awkward manual ones. Remove steps that exist only for historical reasons *before* automating; automating a bad process makes it fast and still bad.

## 4. Build versus buy

| Factor | Buy a tool | Build a custom workflow |
|---|---|---|
| Task is common and well understood | Favoured | |
| Your process is unusual | | Favoured |
| Data is sensitive or must stay in-house | Check carefully | Favoured |
| Need it quickly | Favoured | |
| You have someone to maintain it | | Possible |
| Cost over time | Subscription | Build once, maintain |

Many teams do both: buy the commodity parts and build the glue that fits their process.

## 5. Estimate the return

A simple formula: **time saved per run × runs per month × value of an hour**, minus the cost to build and maintain. Use your own numbers and be conservative. If the answer is close to zero, pick a different task.

## 6. Design the human-in-the-loop

For each automation decide: what is checked automatically, what a person reviews and what is logged. Anything customer-facing or financial needs a human review step.

## 7. Roll out in stages

1. **Pilot** one workflow, running in parallel with the manual version.
2. **Compare** outputs and time spent.
3. **Switch over** with the review step in place.
4. **Document** how it works and who owns it.
5. **Repeat** with the next candidate.

## 8. Common mistakes

- Automating before understanding the process
- No owner after launch
- No logging, so nobody knows when it breaks
- Over-trusting AI output
- Trying to automate everything at once

## 9. Where AI fits

Language models help with text-heavy steps: summarising, drafting, classifying. Plain code and rules are better for exact steps such as calculations and routing. Combine them: code for what has one right answer, models for language, people for judgement.

## FAQ

### What is business automation with AI?

Using software and language models to perform repeatable business tasks, with checks and human review where needed.

### Where should a small business start?

With one frequent, rule-based task such as reporting or lead follow-up, using the audit and scorecard above.

### Should I build or buy?

Buy common, well-understood tools; build where your process is unusual or your data is sensitive. Many teams do both.

### How do I know it is worth it?

Estimate time saved times frequency times the value of an hour, then compare with the cost to build and maintain.

### Is AI output reliable enough?

It needs checks. Verify facts and numbers, and keep a person responsible for the result.
